# 云顶论坛品牌改造方案

本文档用于指导将当前 Discourse 项目改造成一个具有独立品牌形象的专业论坛——`云顶论坛`。

目标是：

- 对外品牌统一为“云顶论坛”
- 所有权与运营主体明确为 `@ydstack`
- 社区方向聚焦大数据、人工智能、Web3，同时兼顾人文、地理与生活延展话题
- 整体视觉和信息架构呈现专业论坛风格
- 尽量减少普通用户可见的 Discourse 默认痕迹

---

# 1. 改造目标

云顶论坛不应只是“换一个 logo 的 Discourse”，而应表现为一个独立的技术社区品牌。

需要达到以下效果：

1. **名称独立**
   - 网站标题统一为 `云顶论坛`
   - 所有公开页面不再以 Discourse 作为主品牌名称

2. **视觉独立**
   - 替换默认 logo、favicon、分享图、邮件 logo
   - 建立自己的配色、首页风格与导航体系

3. **内容结构独立**
   - 围绕大数据、人工智能、Web3、人文、地理等方向建立自己的分类与标签体系
   - 让首页打开后像一个专业社区，而不是默认论坛列表

4. **文案独立**
   - 关于页、欢迎帖、论坛指南、FAQ、法律文本、邮件模板等全部换成云顶论坛自己的叙述

5. **平台归属明确**
   - 所有权、运营主体、联系信息统一体现为 `@ydstack`

---

# 2. 改造原则

建议采用“三层改造法”：

## 2.1 第一层：后台配置替换

优先通过站点设置、分类管理、标签管理、页面文案和主题配置完成品牌替换。

这是成本最低、收益最高的一层。

## 2.2 第二层：主题与主题组件改造

通过主题、主题组件、自定义 CSS/JS、导航增强、首页模块增强等方式，让论坛视觉与结构更贴近“专业产品社区”。

## 2.3 第三层：少量源码覆盖

仅对少数无法通过配置或主题实现的部分进行源码级覆盖，例如：

- About 页残余系统信息
- 某些默认文案
- 少量公开页面中的 Discourse 痕迹
- 独立产品页或品牌首页路由

# 3. 品牌定位建议

## 3.1 品牌名称

- 中文主品牌：`云顶论坛`
- 英文辅助名可选：`Yunding Forum`
- 运营主体：`@ydstack`

## 3.2 品牌口号建议

可选文案如下：

- 面向大数据、人工智能与 Web3 的专业社区
- 聚焦前沿技术、产业实践与开放协作
- 云顶论坛：连接技术、产品与社区

## 3.3 品牌调性建议

建议采用：

- 专业、理性、可信
- 具备技术感，但不过于极客或过于冷硬
- 允许一定的人文与生活延展内容，增强社区温度

# 4. 后台即可完成的改造项

以下内容建议优先通过后台完成，不必先改代码。

## 4.1 站点品牌设置

建议修改以下站点设置：

- `title` → `云顶论坛`
- `short_site_description` → 云顶论坛简短介绍
- `site_description` → 面向大数据、人工智能与 Web3 的专业技术社区
- `company_name` → `@ydstack`
- `contact_email` → 官方联系邮箱
- `notification_email` → 官方通知邮箱
- `site_contact_username` → 官方管理员账号

## 4.2 品牌资源替换

需要准备以下资源并上传替换：

- 主 Logo
- 小 Logo
- 深色模式 Logo
- 移动端 Logo
- Favicon
- Apple Touch Icon
- Open Graph 分享图
- 邮件 Digest Logo

## 4.3 公共页面内容

建议重写以下页面内容：

- 关于我们
- 社区准则
- FAQ
- 隐私政策
- 使用条款
- 欢迎帖
- 新手指引帖
- 发帖规范帖

## 4.4 分类和标签管理

这一部分建议主要通过后台配置完成。

# 6. 标签体系建议

以下更适合作为标签，而不是分类：

- 安装部署
- 资源分享
- 问题求助
- 功能建议
- 开发编程
- 使用分享
- 随便说说
- 版本更新
- 活动公告
- 使用教程
- 请求帮助
- 新手指引
- 产品咨询

## 6.1 标签设计原则

- 标签表达“内容类型”或“交流目的”
- 分类表达“讨论领域”
- 同一标签可以跨多个技术分类复用

例如：

- AI 分类下可以有 `问题求助`
- Web3 分类下也可以有 `问题求助`
- 大数据分类下也可以有 `问题求助`

这样结构更清晰，也更利于搜索与聚合。

# 9. 首页结构建议

如果你想让论坛“打开就像一个专业社区”，首页体验非常关键。

建议首页至少包含以下模块：

## 9.1 Hero 区

展示：

- 云顶论坛主标题
- 一句简洁品牌说明
- 三大核心技术入口：大数据 / AI / Web3
- 快速入口按钮：论坛指南 / 开源产品 / 新手入门

## 9.2 热门方向区

以卡片形式展示：

- 大数据技术
- 人工智能
- Web3
- 人文
- 地理

## 9.3 产品区

展示云顶产品或生态项目：

- 产品名称
- 一句话介绍
- 文档入口
- 社区入口
- GitHub / 下载入口

## 9.4 社区动态区

- 最新活动
- 最新公告
- 最近热门讨论

## 9.5 新手入口区

- 发帖规范
- 标签说明
- FAQ
- 新手指引

# 10. 开源产品页建议

你提到参考论坛中的“开源产品”结构，这一部分非常值得借鉴。

建议为云顶论坛设计一个独立的产品导航页。

## 10.1 页面内容结构

每个产品卡片展示：

- 产品名称
- 产品定位
- 一句话介绍
- 官网链接
- GitHub 链接
- 下载地址
- 文档地址
- 社区板块入口

## 10.2 实现方案

### 方案 A：置顶主题页

最简单，适合快速上线。

### 方案 B：主题组件静态页

最推荐，兼顾品牌感与可维护性。

### 方案 C：自定义路由与页面模板

适合后期做深度品牌门户。

# 11. 去 Discourse 化清单

如果希望用户几乎感知不到 Discourse，需要重点清理以下区域。

## 11.1 必查区域

- About 页面
- 页脚
- 登录页 / 注册页
- 邮件模板
- 分享卡片
- 移动端图标
- 默认欢迎帖
- 默认帮助页
- 默认法律页面

## 11.2 处理方式

### 可通过设置完成的

- 站点名
- 描述
- 联系方式
- logo
- 图标
- 部分 SEO 配置

### 可通过主题完成的

- 首页 Banner
- 顶部导航
- 产品页
- 登录页风格
- 部分公开文案覆盖

### 需要少量源码覆盖的

- About 页面暴露的系统信息
- 个别默认公开文案
- 极少数用户可见的 Discourse 版本或平台提示

# 13. 实施方式建议

## 13.1 第一阶段：基础替换

目标：快速上线云顶论坛品牌。

包括：

- 替换站点名称与描述
- 替换 logo / favicon / OG 图
- 配置联系人与所有权信息
- 创建分类与标签
- 建立欢迎帖与论坛指南

## 13.2 第二阶段：主题改造

目标：让首页与论坛风格具备专业感。

包括：

- 自定义首页 Hero
- 增强导航与左侧栏
- 增加产品页
- 调整配色和分类卡片
- 改造登录页样式

## 13.3 第三阶段：去 Discourse 化

目标：减少用户可见的系统原始品牌痕迹。

包括：

- 覆盖 About 页
- 优化页脚与帮助页
- 检查邮件模板
- 排查默认分享文案与外链品牌信息

## 13.4 第四阶段：持续运营

目标：把论坛真正做成活跃社区。

包括：

- 丰富种子内容
- 规划活动与激励
- 设置精选内容机制
- 形成大数据 / AI / Web3 三个主方向的持续内容供给
