# 核心模块说明

本文档用于说明 Discourse 核心业务模块的职责划分与协作方式。

## 1. 模块划分原则

Discourse 的核心代码虽然属于单体应用，但内部通过清晰的职责边界进行组织，常见分层包括：

- `app/controllers`：请求入口与权限校验
- `app/models`：领域实体与持久化规则
- `app/services`：复杂流程编排
- `app/jobs`：异步任务
- `app/serializers`：API 输出
- `lib/`：基础设施与通用能力

这种结构让项目能够在保持单体部署优势的同时，尽量减少业务耦合。

## 2. 用户与权限模块

用户体系是整个平台的根基，主要围绕以下对象展开：

- 用户账户与资料
- 用户偏好与通知设置
- 群组与成员关系
- Trust Level 信任等级
- 认证与第三方登录
- API Key 与访问控制

权限判断通常通过 `Guardian` 完成。这样做的好处是：

- 权限逻辑集中
- controller 更轻量
- 模型和服务可以复用权限判断
- 插件也能基于统一规则扩展权限

## 3. 内容模块

内容模块负责社区讨论的核心数据结构：

- `Topic`：讨论主题
- `Post`：主题下的帖子
- `Category`：分类
- `Tag`：标签
- `Draft`：草稿
- `Bookmark`：收藏
- `Like`：互动行为

这些实体构成论坛最主要的业务对象，几乎所有页面与 API 都围绕它们展开。

### 3.1 内容生命周期

典型生命周期包括：

1. 用户创建主题或回复
2. 系统进行格式化、清洗与权限检查
3. 数据写入数据库
4. 触发通知、索引、统计等后续流程
5. 前端刷新或拉取最新状态

## 4. 通知与消息模块

通知系统负责将站内事件传达给用户，涵盖：

- 站内通知
- 邮件通知
- 私信提醒
- 订阅与取消订阅
- 实时消息推送

该模块通常会联动：

- serializer
- mailer
- job
- MessageBus / 实时通知能力

Discourse 非常重视“触达”，因此通知链路是核心体验之一。

## 5. 审核与治理模块

社区平台必须具备治理能力。Discourse 内置了比较完整的治理体系：

- 举报与审核队列
- 风控与反垃圾
- 屏蔽词/邮件/IP/URL 过滤
- Staff Action Log
- 审核对象 `Reviewable`

这一模块的目标是让管理员和版主能够处理违规内容、异常用户与高风险操作。

## 6. 搜索模块

搜索模块负责让用户快速定位内容。它包括：

- 帖子和主题索引
- 标签索引
- 搜索日志
- 索引重建任务
- 插件自定义搜索数据

核心系统对搜索的支持较深，插件也可以注册自己的搜索索引，例如聊天消息索引。

## 7. 上传与媒体模块

上传与媒体模块处理：

- 图片和附件上传
- 外链预览
- 视频/音频引用
- 对象存储集成
- 上传安全校验
- 图片压缩与优化

这部分与文件存储、内容解析和安全控制紧密相关。

## 8. 站点设置与配置模块

Discourse 提供高度可配置的站点设置系统，主要包括：

- 全局设置 `GlobalSetting`
- 站点设置 `SiteSetting`
- 设置依赖与校验
- 默认值提供
- 多站点配置

这让站点管理员能够在不修改代码的情况下调整大量行为。

## 9. 主题与外观模块

主题模块负责：

- 主题资源
- 样式编译
- JS 编译
- 翻译覆盖
- 主题设置
- 主题导入导出

它使平台在保证核心稳定的前提下，拥有很强的外观和交互定制能力。

## 10. 异步与后台任务模块

后台任务是 Discourse 架构的重要组成部分，主要用于处理：

- 邮件发送
- 搜索索引更新
- 清理过期数据
- 文件处理
- 统计与报表
- 外部集成同步

这些任务避免了在主请求线程中执行高成本操作，从而保持响应速度。

## 11. 模块协作关系

常见协作模式如下：

- Controller 接收请求并调用 Service
- Service 处理业务并调用 Model
- Model 负责数据规则与持久化
- Job 承接耗时异步工作
- Serializer 组织响应输出
- Plugin 通过扩展点影响上述模块

这种结构使系统保持了较好的可维护性，同时又能支撑复杂业务演进。

## 12. 核心模块总结

Discourse 的核心模块并不是简单按功能堆砌，而是围绕“用户、内容、通知、治理、搜索、上传、配置、异步任务”这几个关键领域构建。它们共同构成了社区平台的主干能力。
