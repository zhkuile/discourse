# 云顶论坛信息架构方案

本文档用于规划云顶论坛的分类、标签、导航、首页模块和产品入口结构，帮助论坛从默认通用社区形态转变为具有明确品牌和内容方向的专业社区。

## 1. 信息架构目标

云顶论坛的信息架构需要同时满足以下目标：

- 让用户一进入论坛就知道这是“云顶论坛”
- 明确覆盖技术主线：大数据、人工智能、Web3
- 兼顾人文、地理和贴近生活的话题延展
- 支持新用户快速找到入口
- 支持老用户按分类和标签持续跟踪内容
- 支持后续扩展云顶自己的产品矩阵

## 2. 一级结构原则

建议把论坛内容拆成三大层：

1. **官方入口层**
   - 论坛指南
   - 新手入口
   - 活动公告
   - 开源产品

2. **核心内容层**
   - 大数据
   - 人工智能
   - Web3

3. **延展讨论层**
   - 人文
   - 地理
   - 生活随谈

这样既保留专业感，也不会显得过于狭窄。

## 3. 顶部导航建议

推荐顶部导航按“用户目标”而不是“系统功能”来设计。

### 推荐导航

- 首页
- 论坛指南
- 开源产品
- 大数据
- 人工智能
- Web3
- 人文
- 地理
- 活动公告
- 关于云顶

### 可选精简版

如果担心导航过长，可以使用：

- 首页
- 论坛指南
- 开源产品
- 技术社区
- 人文生活
- 活动公告
- 关于云顶

其中：

- 技术社区下承载大数据、人工智能、Web3
- 人文生活下承载人文、地理、生活随谈

## 4. 左侧边栏建议

左侧边栏适合展示“常用入口”和“内容筛选入口”，建议分组，而不是把所有项目平铺。

### 4.1 社区入口

- 新手指引
- 论坛指南
- 使用教程
- 请求帮助
- 所有标签

### 4.2 技术交流

- 安装部署
- 资源分享
- 问题求助
- 功能建议
- 开发编程
- 使用分享
- 产品咨询

### 4.3 社区动态

- 版本更新
- 活动公告
- 随便说说

### 4.4 用户自定义区

建议保留用户自定义边栏能力，让用户自行关注：

- 常看分类
- 常用标签
- 收藏主题
- 个人草稿

## 5. 分类体系建议

## 5.1 官方区

### 社区公告

用途：
- 官方通知
- 系统变更
- 活动公告
- 社区规则

### 新手专区

用途：
- 新手指引
- 论坛使用教程
- 发帖规范
- 常见问题

### 云顶产品

用途：
- 产品介绍
- 发布动态
- 使用说明
- 产品讨论入口

## 5.2 技术主区

### 大数据技术

建议二级方向：
- 数据平台
- 数据仓库
- 实时计算
- 湖仓一体
- 数据治理
- 数据分析

### 人工智能

建议二级方向：
- 大模型 / LLM
- AIGC
- Agent
- RAG / 向量数据库
- 模型部署
- AI 工程实践

### Web3

建议二级方向：
- 区块链基础设施
- 智能合约
- 链上数据
- 钱包与身份
- DeFi / NFT
- Web3 安全

## 5.3 延展区

### 人文

建议话题方向：
- 阅读与思考
- 历史与文化
- 社会议题
- 观点讨论

### 地理

建议话题方向：
- 地缘观察
- 城市与区域
- 旅行见闻
- 地图与空间认知

### 生活随谈

建议话题方向：
- 随便说说
- 社区闲聊
- 工作与生活
- 轻松话题

## 6. 标签体系建议

建议把“使用意图”和“内容类型”做成标签，而不是分类。

### 推荐标签

- 安装部署
- 资源分享
- 问题求助
- 功能建议
- 开发编程
- 使用分享
- 版本更新
- 活动公告
- 使用教程
- 请求帮助
- 新手指引
- 产品咨询
- 随便说说

### 进一步建议

还可以按技术栈补充专业标签，例如：

- Spark
- Flink
- Kafka
- ClickHouse
- Airflow
- LangChain
- RAG
- LLM
- Solidity
- Rust
- Ethereum
- K8s
- Docker

## 7. 首页结构建议

首页是决定“看起来像不像自己的论坛”的关键。

建议首页至少包含以下模块：

### 7.1 Hero Banner

展示：
- 云顶论坛主标题
- 一句话品牌定位
- 社区介绍摘要
- 主要入口按钮

建议文案示例：

- 标题：云顶论坛
- 副标题：聚焦大数据、人工智能、Web3 与延展议题的专业社区
- 按钮：进入论坛指南 / 查看开源产品 / 浏览最新讨论

### 7.2 三大技术入口

卡片入口：
- 大数据
- 人工智能
- Web3

### 7.3 延展话题入口

卡片入口：
- 人文
- 地理
- 生活随谈

### 7.4 官方内容区

显示：
- 社区公告
- 活动公告
- 版本更新
- 新手专区

### 7.5 热门内容区

显示：
- 热门主题
- 最新讨论
- 推荐资源

### 7.6 开源产品区

产品卡片建议包含：
- 产品名称
- 一句话介绍
- 文档入口
- GitHub
- 下载链接
- 对应论坛板块

## 8. 开源产品页建议

如果你要参考 FIT2CLOUD 的“开源产品”入口，建议单独设计一个产品页。

### 页面结构建议

每个产品卡片包含：

- 产品名称
- 产品定位
- 一句话价值说明
- 产品文档
- 下载链接
- GitHub 地址
- 社区讨论入口

### 产品页内容分组建议

- 数据平台类产品
- AI 类产品
- Web3 工具类产品
- 其他实验型产品

## 9. 默认内容初始化建议

信息架构不仅是分类和导航，也包括内容入口。

建议上线前准备以下置顶内容：

- 欢迎来到云顶论坛
- 新手必读
- 论坛使用指南
- 发帖规范
- 标签使用说明
- 云顶产品导航
- 社区价值观与规则

每个核心分类建议至少准备 3~5 个种子话题。

## 10. 用户路径设计建议

### 新用户路径

首页 → 新手指引 → 论坛指南 → 选择分类 → 发帖或关注

### 技术用户路径

首页 → 技术分类 → 标签筛选 → 浏览问题/教程/资源 → 参与讨论

### 产品用户路径

首页 → 开源产品 → 进入产品卡片 → 文档 / 下载 / 社区讨论

## 11. 实施建议

建议按以下顺序落地：

1. 先创建分类和标签
2. 再配置边栏和导航
3. 再建立置顶内容和产品入口
4. 再用主题组件增强首页
5. 最后对少量公开页面做品牌覆盖

## 12. 结论

云顶论坛最适合采用“官方入口 + 技术主区 + 延展讨论区”的信息架构。这样既能保持专业技术社区形象，又能让论坛更有内容生命力和品牌辨识度。
